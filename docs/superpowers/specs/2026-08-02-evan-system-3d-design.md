# Evan System — Blueprint → Reality: 인터랙티브 3D 메인 경험 설계

날짜: 2026-08-02
상태: 사용자 승인 대기

## 1. 목표

메인 페이지를 "슬라이드 전환이 있는 2D 사이트 + 우주 배경"에서 **하나의 몰입형
3D 항성계 경험**으로 전환한다. 방문자가 받아야 할 인상은 세 가지다:

- **기술력** — "이걸 브라우저에서 직접 만들었다고?"
- **예술성** — 아트 디렉션과 연출의 완성도
- **서사** — "아이디어를 현실로 만드는 개발자·창업가 Evan"이 공간으로 그려짐

타겟은 리크루터(빠른 경로 필수)와 탐험가(깊은 경험) 둘 다. 모바일 동등 경험과
저사양 기기 배려는 하드 제약이다.

## 2. 핵심 컨셉

> 방문자는 어둠 속에서 **청사진이 그려지고 실체화되는 항성계**에 도착한다.
> 각 행성이 About·Skills·Projects·Contact이고, 스크롤은 페이지 넘김이 아니라
> **행성 사이를 항행하는 카메라**다. Evan이 아이디어를 현실로 만들듯, 세계의
> 모든 것은 선(설계)에서 실체(제품)로 빌드된다.

두 축의 결합:

- **Evan System** (공간 구조): 메인 = 항성계. 중심 항성(Hero) + 궤도 행성들
  (About, Skills, Projects 위성군, Contact). Lab은 외곽 소행성대, Guestbook은
  방문자 신호가 모이는 행성. 기존 우주 자산(워프, 궤도 하강, 지구본, 실험별
  `planet` 메타데이터)을 전부 하나의 세계로 승격.

**아트 디렉션 제약(사용자 확정)**: 배경은 현재 사이트의 정체성인 **검은 우주 +
떠다니는 별** 룩을 유지한다. 새 씬은 이 배경을 교체하는 것이 아니라 그 위에
쌓아 올리며, 전체적으로 "고퀄리티 우주" — 사진적 깊이감이 느껴지는 렌더링
품질을 목표로 한다(구현 수단은 5.3 참조).
- **Blueprint → Reality** (시각 언어): 모든 오브젝트는 청사진 선 드로잉 →
  와이어프레임 → 실체 렌더 순으로 "빌드"된다. About 카피 "아이디어를 완벽한
  현실로 만들어냅니다"의 시각화.

## 3. 경험 흐름 (첫 방문)

1. **로딩 = 설계 단계.** 검은 화면에 청사진 그리드가 깔리고 로딩 진행도에 따라
   항성계 설계 선이 그려진다. 로딩 화면이 곧 인트로다.
2. **실체화 순간.** 설계 완성 → 선이 빛으로 점화되며 항성계가 3D로 일어선다 →
   카메라가 진입한다(기존 warp/arrivalSequence 연출을 이 순간으로 승격).
3. **Hero.** 중심 항성 앞 정거장. 타이틀·타이핑 텍스트는 HTML 오버레이 유지.
4. **스크롤 = 카메라 레일.** 항성 → About → Skills → Projects 위성군 → Contact
   순으로 항행. 정거장 도착 시 그 행성이 청사진→실체로 빌드되며 HTML 콘텐츠
   패널이 옆에 도킹된다.
5. **Projects.** 각 프로젝트는 자기 `accent` 색을 띤 위성. 선택 시 카메라가
   위성으로 다가가고 상세 페이지로 연결.
6. **내비게이션.** 구석 미니맵(항성계 지도)이 현재 위치를 표시하고 클릭 시
   순간이동. 네비바의 **오토파일럿**은 30초 자동 투어(정거장별 잠깐 정차,
   스크롤/클릭으로 언제든 인터럽트). 이력서·연락처는 항상 1클릭.
7. **세계 통합.** `/gallery`(Lab)는 소행성대로, `/guestbook`은 신호 행성으로
   항성계에서 시각적으로 존재하며, 라우트 이동은 워프 전환으로 연결된다.

## 4. 살아있는 세계

- **시간대 라이팅**: 방문자의 로컬 시간이 씬 라이팅·톤에 반영된다(밤에 오면
  깊은 밤의 항성계).
- ~~**방문자 흔적**: Supabase의 방명록·방문 데이터가 배경 신호점/별빛으로
  축적된다.~~ **범위에서 제외(2026-08-08)** — 방명록은 이미 `/guestbook`
  라우트에 Supabase로 구현돼 있어 방문자 데이터가 사이트에 남는다는 목적은
  이미 달성됐다. 같은 데이터를 배경 별빛으로 한 번 더 표현하는 것은 새 가치
  없이 씬 복잡도와 네트워크 의존만 늘린다.

## 5. 기술 아키텍처

### 5.1 씬 구조

- 현재 SpaceBackground(순수 three.js 명령형 + 순수 로직 모듈 단위 테스트
  패턴)를 **항성계 스테이지로 확장**한다. R3F는 코드베이스 어디에서도 쓰이지
  않으므로 도입하지 않는다 — 기존 워프/도착 시퀀스 렌더 루프와 한 루프에서
  일관되게 돌리는 것이 안전하다. 라우트가 바뀌어도 캔버스는 유지되고 씬
  상태만 전환(메인=항성계 스테이지, 다른 라우트=워프/배경 모드).
- 섹션 콘텐츠는 **기존 HTML 컴포넌트를 그대로 도킹 패널로 표시**한다.
  SEO·접근성·i18n·기존 4개 모드(Terminal/Speedrun/Destruction/Inspect)가 전부
  보존된다. Destruction의 DOM 스냅샷도 계속 동작한다.

### 5.2 카메라 레일

- Lenis 스크롤 진행도 → Catmull-Rom 커브 파라미터로 매핑. 섹션 앵커(`#about`
  등)는 레일 위 정거장 좌표로 동작해 기존 해시 내비게이션과 호환된다.
- 정거장 스냅: 스크롤 정지 시 가장 가까운 정거장에 정착(현재 슬라이드 스냅
  로직의 3D 버전).

### 5.3 렌더링 품질 — 커스텀 GLSL 셰이더 (사용자 확정)

렌더링 품질은 애플리케이션 언어가 아니라 GPU 셰이더가 결정한다. 앱은
React+three.js를 유지하고, 품질을 결정하는 층은 **커스텀 GLSL**로 직접
작성한다(기존 sky.glsl·warp 셰이더의 확장 노선).

- **Blueprint 머티리얼**: 선 드로잉 → 와이어프레임 → 실체 렌더로
  크로스페이드되는 공용 셰이더. 행성·위성·장식 오브젝트에 일괄 적용해 시각
  언어를 통일한다. 빌드 진행도는 uniform 하나로 구동해 정거장 도착 타이밍·
  오토파일럿·reduced-motion 폴백에서 동일하게 제어한다.
- **별 필드**: 현재의 "검은 우주 + 떠다니는 별" 룩을 계승한 GLSL 파티클 별
  필드 — 반짝임(twinkle), 원근 페럴랙스, 카메라 항행 시 미세 스트리킹.
- **성운/딥스페이스 배경**: FBM 노이즈 기반 성운 셰이더를 배경 레이어에 얕게
  깔아 깊이감을 만들되, 검은 우주가 주인공인 현행 톤을 해치지 않는 밀도로.
- **행성 표면**: 행성별 절차적(procedural) 표면 셰이더 — 노이즈 기반 지형·
  대기 프레넬 림 라이트·야간면 글로우. 텍스처 다운로드 없이 고품질.
- **항성**: 코로나 글로우 + 표면 난류 노이즈 셰이더.
- **포스트프로세싱**: 선택적 블룸·필름 그레인·비네트(기존 postfx.js 확장).
  품질 프리셋(5.4)에 따라 단계적으로 비활성화.

### 5.4 품질 스케일링·폴백

- 첫 프레임 GPU 티어 감지 → high/mid/low 프리셋(파티클 수, DPR, 포스트FX).
  기존 HardwareAccelNotice 로직을 확장한다.
- `prefers-reduced-motion`·최저 티어: 빌드 연출을 정적 페이드로, 카메라 이동을
  단순 컷으로 대체.
- WebGL 불가: 현재의 2D 구조(데스크톱=슬라이드 전환, 모바일=세로 스크롤)를
  폴백으로 유지한다.

### 5.5 모바일

- 축소판이 아닌 동일 항성계. 터치 스크롤 항행 + 드래그 시점 미세 회전,
  자이로 패럴랙스는 opt-in.
- 현재의 `isDesktop` 분기(모바일=일반 세로 스크롤)는 3D 레일 방식으로
  대체하되, 저사양 모바일은 5.4 폴백을 따른다.

## 6. 단계별 구축 (한 스펙, 6단계 출시)

| Phase | 내용 | 완료 기준 |
|---|---|---|
| 1 | 항성계 씬 + 카메라 레일 + 섹션 HTML 도킹 (코어 구조 교체) | 이 단계만으로 완결된 경험. 기존 모드·해시내비·i18n 전부 동작 |
| 2 | Blueprint 머티리얼 + 로딩→실체화 인트로 | 시그니처 연출 완성 |
| 3 | **렌더링 품질 — 행성 절차적 표면·항성 코로나·성운 배경·필름 그레인** | 실체화가 끝난 뒤의 화면이 "고퀄리티 우주"로 읽힘 |
| 4 | 미니맵 + 오토파일럿 투어 | 리크루터/탐험가 듀얼 트랙 완성 |
| 5 | 살아있는 세계 — **시간대 라이팅만** (Supabase 방문자 흔적은 §4에서 범위 제외) | 방문 시각이 항성계의 빛에 드러남 |
| 6 | 폴리시 — **프로젝트 위성 디오라마 + 앰비언트 오디오(Web Audio 합성, 음소거 기본 + 유도형 토글)**. 헤드트래킹 패럴랙스는 범위 제외 | 심화 완성 |

**Phase 6 범위 확정 (2026-08-09)**: 세 항목은 서로 의존하지 않는 독립 하위 시스템이라
각각 별도 플랜으로 순차 출시한다.

- **헤드트래킹 패럴랙스는 제외한다.** 메인 페이지에서 카메라 권한을 요구하게 되는데,
  opt-in이라도 리크루터가 허용할 가능성이 낮고 권한 프롬프트 자체가 첫인상을 해친다.
  같은 기술은 이미 Lab의 CosmicMirror 실험에 있고, 그쪽이 방문자의 기대와 맞는 자리다.
- **앰비언트 오디오는 파일이 아니라 Web Audio로 합성한다.** 저장소에 오디오 자산이
  하나도 없어 파일을 도입하면 용량과 라이선스가 따라온다. 오실레이터·필터로 직접
  만들면 두 문제가 없고, "브라우저에서 직접 만들었다"는 이 사이트의 이야기와도 맞는다.

각 Phase는 독립적으로 배포 가능해야 한다.

**Phase 3 순서 변경 이유 (2026-08-05)**: Phase 2까지 마친 뒤 실물을 확인해 보니, 인트로가
끝나고 드러나는 행성이 단색 구체(`MeshStandardMaterial`)라 연출의 클라이맥스가 받쳐지지
않았다. §5.3이 계획한 셰이더 항목 중 Blueprint만 구현된 상태였다. 기능(미니맵·오토파일럿)
보다 "고퀄리티 우주"라는 원 요구를 먼저 충족시키는 것이 맞다고 판단해 렌더링 품질을
Phase 3으로 올리고 이후 단계를 한 칸씩 밀었다.

**별 필드는 이 재정렬에서 제외한다.** §5.3은 별 필드의 GLSL 재작성도 계획했지만,
"검은 우주 + 떠다니는 별" 룩은 사용자가 두 번 못박은 아트 디렉션이고 현재 구현이 이미
그 룩을 만들고 있다. 같은 룩을 다시 만들어내는 재작성은 이득 대비 시각 회귀 위험이
커서 손대지 않는다.

## 7. 성공 기준

- 데스크톱 중티어 GPU에서 60fps, 저티어에서 프리셋 강등 후 60fps 유지.
- 모바일(중급 기기)에서 동일 컨셉의 경험이 끊김 없이 동작.
- 첫 인터랙션 가능 시점(로딩 인트로 완료) 3초 이내(캐시 없는 중속 회선 기준).
- 기존 기능 무손실: 4개 모드, 해시 내비게이션, i18n 4개 언어, Lab/Guestbook
  라우트, Supabase 연동.
- 리크루터 경로: 진입 → 이력서 다운로드까지 2클릭 이내, 오토파일럿 30초 투어.

## 8. 명시적 비범위 (Out of Scope)

- 섹션 텍스트·카드의 풀 3D화 (HTML 도킹 패널로 확정).
- 동시 접속자 실시간 표시 (추후 검토).
- Lab 실험들 자체의 리뉴얼 (항성계와의 "연결"만 이번 범위).
- 음성/대화형 AI 에이전트 내비게이션.
