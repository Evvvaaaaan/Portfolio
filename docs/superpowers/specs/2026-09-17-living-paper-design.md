## 1. 목표와 핵심 경험

직접 쓴 HTML 문서가 종이처럼 휘었다가 다시 펼쳐지는 독립적인 전체 화면 Lab을 만든다. HTML-in-Canvas로 실제 HTML을 텍스처에 그리며, 평평하게 펼친 상태에서 문서 안의 입력과 텍스트 선택이 동작하는 것을 핵심 가치로 삼는다.

방문자는 짧은 문장을 적고, 종이 가장자리를 당겨 형태를 바꾸고, 손을 놓아 종이가 돌아오는 모습을 본다. 다시 펼치면 작성한 문장을 계속 수정할 수 있다. 이 흐름을 설명 없이도 발견할 수 있도록 첫 화면에는 종이 한 장과 조작 안내 한 줄만 강조한다.

사용자가 선택한 콘셉트는 Living Paper다. Prism과 Spatial Desk는 이번 범위에 포함하지 않는다.

- 편집 안내: `문장을 바꿔보세요.`

기술 설명은 접힌 정보 영역에 둔다. 브라우저 지원 여부가 사용 가능 기능을 바꾸는 경우에만 간단한 안내를 노출한다.

## 4. 방문 흐름과 조작 규칙

1. 지원 환경에서는 읽을 수 있을 정도로만 살짝 휜 종이가 나타난다. 짧은 안내로 모서리 조작과 글 쓰기를 제시한다.
2. `글 쓰기`를 누르면 종이가 정면의 평면으로 펼쳐진다. 펼침이 끝난 뒤 입력 영역으로 포커스를 옮긴다.
3. 제목과 본문을 편집하면 HTML 변경이 캔버스에 반영된다. 한글 조합 입력, 커서, 선택 영역을 확인할 수 있어야 한다.
4. `종이 만지기`로 전환하면 입력값을 유지한 채 모서리를 당길 수 있다. 놓으면 감쇠하며 원래 모양으로 돌아온다.
5. 바람 세기로 작은 일렁임을 조절하고, `펴기`를 누르면 정면의 편집 상태로 돌아간다.

드래그는 명시적인 손잡이에서 시작한다. 편집 상태의 본문 드래그는 텍스트 선택으로 사용하며 장면 조작에 빼앗기지 않는다. 초기 구현은 한 모서리의 말림과 약한 바람 변형으로 제한한다. 실제 종이의 찢김, 충돌, 접힌 면끼리의 충돌을 계산하는 전체 물리 시뮬레이션은 범위 밖이다.

### 상태별 입력과 접근성

| 상태 | 표시와 입력 |
|---|---|
| 종이 만지기 | 곡면 변형과 손잡이 조작이 가능하다. 문서 내부의 편집·텍스트 선택은 잠근다. 외부의 편집 전환 버튼은 항상 접근 가능하다. |
| 글 쓰기 | 종이 변형과 카메라 움직임을 멈추고 실제 HTML 입력·선택·포커스를 활성화한다. |
| 전환 중 | 문서 내부 입력을 잠시 잠그고, 평면과 좌표 동기화가 완료된 다음 포커스를 복원한다. |
| 미지원 환경 | 캔버스 밖에서 같은 문서를 일반 HTML로 표시한다. 제목과 본문 편집은 유지한다. |

곡면의 각 점은 서로 다른 방향으로 움직이므로 단일 `DOMMatrix`로 전체 문서의 입력 위치를 정확하게 표현할 수 없다. 따라서 곡면 상태에서 네이티브 텍스트 선택까지 지원한다고 약속하지 않는다. 편집 상태에서는 평면 투영에 맞는 좌표를 동기화한다.

숨겨진 입력이 Tab 순서에 남지 않도록 상태에 따라 `inert`와 포커스를 관리한다. 동일한 문서를 두 개의 접근 가능한 DOM 트리로 중복 제공하지 않는다. 모서리 조작은 키보드로도 변화시킬 수 있고, 편집 전환과 펴기는 실제 HTML 버튼으로 제공한다.

모바일은 종이와 조작부를 세로로 배치한다. 가상 키보드가 올라오면 편집 영역이 가려지지 않게 조정한다. `prefers-reduced-motion` 환경은 펼친 상태로 시작하며 자동 바람과 진입 움직임을 끈다.

## 5. HTML-in-Canvas 적용과 호환성

2026-09-17에 읽은 [WICG explainer](https://github.com/WICG/html-in-canvas)는 실험 플래그를 사용하는 API로 안내한다. 현재 문서에는 `layoutsubtree`, `drawable`, `paint`, `drawElementImage`, WebGL의 `texElementSubImage2D`, `updateElementGeometry`가 포함되어 있다.

[Chrome의 2026-05-19 안내](https://developer.chrome.com/blog/html-in-canvas-origin-trial)는 Chrome 148–150 Origin Trial과 이전 API 형태를 설명한다. 이 안내만으로 현재 공개 배포에서 플래그 없이 작동한다고 판단하지 않는다. 현재 [WICG WebGL 예제](https://github.com/WICG/html-in-canvas/blob/main/Examples/webGL.html)에도 API 변경에 대한 대응 코드가 있다.

구현 전 목표 브라우저의 실제 버전과 플래그 상태를 기록하고, 새 API의 렌더링과 입력 동작을 검증한다. 브라우저 이름 대신 필요한 기능의 존재 및 실제 첫 렌더링 성공을 판단 기준으로 사용한다. 이 기획 단계에서는 브라우저 런타임 검증을 수행하지 않았다.

권장 초기 구조는 페이지 전용 WebGL2 렌더러다. 한 장의 종이만 그리는 범위에서 현재 네이티브 업로드 API를 직접 사용하면 기존 Three.js 전체 업그레이드 없이 검증할 수 있다. 사전 검증 후 확정하며, 기존 r184 `HTMLTexture`를 그대로 사용한다는 전제는 두지 않는다.

- React가 문서 내용과 조작 상태를 관리한다. 지원 경로에서는 문서를 해당 캔버스의 DOM 자식으로 둔다.
- 브라우저가 HTML과 CSS를 배치하고, `paint`에서 초기 스냅샷이 준비된 뒤 텍스처를 업로드한다. 이후 내용이 바뀐 경우에 갱신한다.
- WebGL은 종이 메시의 변형과 명암을 그린다. 종이만 움직일 때 HTML 텍스처를 불필요하게 다시 캡처하지 않는다.
- 편집 상태에서는 `updateElementGeometry`로 표시 위치와 HTML 입력 위치를 맞춘다. 캔버스의 CSS 크기와 장치 픽셀 크기를 구분한다.
- 화면 크기나 글꼴 준비 상태가 바뀌면 레이아웃, 텍스처 크기, 입력 좌표를 함께 갱신한다.
- API 미지원 또는 초기화 실패 시 문서를 캔버스 밖의 일반 HTML로 표시한다. 입력 데이터는 같은 상태에서 유지한다.

대체 화면의 문구는 `현재 브라우저에서는 문서 편집을 사용할 수 있어요. 종이 효과는 실험 기능을 지원하는 브라우저에서 열립니다.`로 제안한다. 자세한 실험 설정은 사용자가 펼쳤을 때 제공한다. 캔버스 자체의 fallback 자식이 자동으로 화면에 표시된다고 가정하지 않는다.

초기 버전은 로컬 문서와 같은 출처의 자산을 사용한다. 외부 웹사이트 임베드, 전체 홈페이지 캡처, 외부 이미지 업로드는 넣지 않는다. 저장·공유 서버나 이미지·영상 내보내기도 이번 범위에 포함하지 않는다.

## 7. 구현 순서와 완료 기준

| 단계 | 작업 | 다음 단계로 넘어갈 확인 조건 |
|---|---|---|
| 0. 기술 검증 | 변경 전 `npm test`와 관련 갤러리 테스트의 기준 결과를 확보한다. 목표 브라우저에서 작은 HTML 입력 요소로 네이티브 캔버스 렌더링 및 WebGL 업로드를 확인한다. | 실제 텍스처의 내용 갱신, 평면에서의 클릭·Tab·한글 입력·선택을 직접 확인한다. 실패 시 원인을 조사하고 렌더링 구조를 확정하기 전 결과를 보고한다. |
| 1. 문서와 평면 | 단일 문서의 편집, 일반 HTML 대체 화면, 상태 유지, 접근 가능한 버튼을 구성한다. | 입력값이 모드 전환에 보존된다. API가 없는 환경도 빈 화면 없이 문서를 편집할 수 있다. |
| 2. 종이 표현 | 모서리 말림, 감쇠 복원, 바람, 펼침 전환을 구현한다. | 문구를 수정한 다음 종이를 휘어도 수정된 내용이 보인다. 다시 펼쳤을 때 클릭 위치와 커서가 일치한다. |
| 3. 통합과 검증 | 갤러리에 등록하고 모바일·동작 줄이기·정리 로직을 점검한다. | `npm test`, `npm run lint`, `npm run build`, 관련 Playwright 테스트를 실행한다. 기존 실패와 신규 실패를 구분하고 실제 브라우저 수동 확인 결과를 남긴다. |

핵심 인수 시나리오는 “한글 문장 입력, 종이 모드 전환, 모서리 당기기, 복원, 다시 편집”이다. 네이티브 API가 꺼진 환경의 통과 결과로 켜진 환경의 성공을 대신하지 않는다.

추가 확인 항목:

- 실제 API 호출로 HTML이 그려지는지 확인하며 정적 이미지로 대체한 결과를 기술 검증 성공으로 처리하지 않는다.
- 편집 상태에서 선택·복사, 브라우저 찾기, 포커스 표시를 직접 확인한다. VoiceOver에서 읽기 순서와 컨트롤 이름을 점검한다.
- 리사이즈, 브라우저 확대, 고해상도 화면에서 텍스처 선명도와 클릭 좌표를 확인한다.
- 문서 드래그와 손잡이 드래그가 충돌하지 않고 모바일에서도 편집을 마칠 수 있다.
- 페이지를 떠나면 렌더링 루프, 이벤트, 관찰자, WebGL 자원을 정리한다.
- 동작 중 데스크톱 60fps를 목표로 실제 장치에서 측정한다. 미달 시 렌더 해상도와 메시 밀도를 낮춘다. 측정 전 성능을 보장하지 않는다.

## 8. 이번 기획의 검증 범위

저장소의 경로·레지스트리·기존 실험·테스트 설정과 설치된 Three.js 구현을 읽었고, WICG 최신 문서 및 공식 예제를 대조했다. 브라우저별 네이티브 API 실행, 종이 표현, 성능, 접근성은 아직 검증하지 않았다. 앱 소스 수정, 테스트 실행, 배포는 이 기획 작업에 포함하지 않았다.

## 9. 시각·인터랙션 확장

초기 구현 후 “좀 더 시각적으로 풍성하고 다양한 인터랙션” 요청에 따라 코튼·블루프린트·로즈 재질, 세 가지 도장과 되돌리기, 네 모서리의 독립적인 접기, 접촉 파동, 순간 바람, 포인터 조명을 추가했다. 재질과 도장은 실제 문서 내용에 반영하며, 미지원 브라우저에서도 편집과 함께 사용할 수 있다. 동작 줄이기에서는 자동 움직임과 순간 효과를 끈다. 구체적인 검증 결과는 구현 기록에서 관리한다.
