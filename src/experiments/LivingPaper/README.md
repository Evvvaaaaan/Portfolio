# Living Paper

경로: `/gallery/living-paper`

HTML 문서를 네이티브 HTML-in-Canvas API로 WebGL 텍스처에 그리는 Lab이다. 제목과 본문을 쓴 뒤 모서리를 당기고 바람을 조절할 수 있다. `글 쓰기` 또는 `펴기`를 누르면 종이가 평면으로 돌아오고 실제 HTML 입력을 다시 사용할 수 있다. 작성 내용은 페이지를 떠나면 사라진다.

## 시각·인터랙션 확장

- 코튼, 블루프린트, 로즈 재질은 종이의 색, 인쇄 패턴, 잉크, 뒷면과 화면 강조색을 함께 바꾼다. 글은 유지된다.
- 네 모서리를 각각 안쪽으로 당길 수 있다. 방향키의 안쪽 방향, Space 또는 Enter로 접고 반대 방향으로 펼친다. 손을 놓으면 원래 모양으로 돌아온다.
- 종이를 직접 클릭하거나 `톡 건드리기`를 누르면 접촉 위치에서 파동이 퍼진다. `바람 불기`는 일시적인 큰 일렁임을 만든다. 연속 바람은 기존 슬라이더로 조절한다.
- 종이 위에서 포인터를 움직이면 조명 방향이 천천히 바뀐다. 입자, 가장자리 명암, 표면 반사와 배경의 인쇄 가이드를 추가했다.
- `도장 찍기`는 최대 세 개의 도장을 문서에 찍는다. 마지막 도장을 순서대로 지울 수 있다. 도장은 실제 HTML이므로 종이와 함께 변형되며 미지원 환경에서도 사용할 수 있다.
- 동작 줄이기에서는 자동 바람, 파동, 순간 바람, 포인터 조명을 끈다. 키보드와 손잡이로 지정한 접기는 즉시 반영한다. 재질과 도장도 계속 사용할 수 있다.

## 실행

```sh
npm run dev
```

지원되는 Chrome에서 `chrome://flags/#canvas-draw-element`를 활성화하고 브라우저를 다시 시작한다. 플래그가 꺼져 있거나 네이티브 API 또는 WebGL 초기화가 실패하면 일반 HTML 문서 편집 모드로 열린다. 브라우저 전체를 자동으로 재실행하거나 사용자 설정을 변경하지 않는다.

## 렌더링

- `LivingPaper.jsx`는 문서 데이터와 모드를 관리한다. 캔버스 자식 문서와 대체 화면은 같은 React 상태를 사용하며 동시에 두 개의 문서를 표시하지 않는다.
- `scene.js`는 `paint` 이벤트에서 HTML 텍스처를 갱신한다. 종이 변형은 별도 렌더링 루프에서 처리하며 HTML을 매 프레임 캡처하지 않는다.
- `paper.js`의 동일한 투영 계산이 종이 메시와 네 모서리 손잡이의 위치를 결정한다. 독립적인 원통형 말림, 바람 변형, 감쇠 파동과 복원을 사용하며 전체 종이 물리 시뮬레이션은 아니다.
- 편집할 때는 변형을 제거하고 HTML의 입력 좌표를 맞춘다. 곡면 상태에서는 문서에 `inert`, `aria-hidden`, 읽기 전용, 탭 제외 상태를 적용한다. 실험 API에서 `inert`만 적용하면 입력이 접근성 트리에 남는 현상을 확인했기 때문이다.
- 그래픽 컨텍스트를 잃으면 문서 내용을 유지한 채 일반 HTML 편집으로 전환한다. 페이지를 떠나면 이벤트, 관찰자, 타이머와 그래픽 자원을 정리한다.

## 브라우저 API 버전

Chrome 152.0.7977.83은 `texElementImage2D(target, internalFormat, element)`를 사용한다. Playwright Chromium 148.0.7778.96은 이전의 6개 인자 형식을 사용한다. 두 형식 모두 실제 브라우저에서 검증한다. Three.js r184의 전역 업그레이드는 필요하지 않다.

[현재 WICG 문서](https://github.com/WICG/html-in-canvas)의 `texElementSubImage2D`와 `updateElementGeometry`가 있으면 해당 경로를 사용한다. 로컬에 설치된 두 브라우저에는 이 최신 형식이 없어 해당 분기는 런타임 검증하지 못했다. 참고한 [공식 WebGL 예제](https://github.com/WICG/html-in-canvas/blob/main/Examples/webGL.html) 역시 API 변경에 따른 여러 호출 형식을 다룬다.

## 검증 명령

```sh
npm test
npm run build
npx eslint src/experiments/LivingPaper src/experiments/index.js e2e/living-paper.spec.js e2e/lab-gallery.spec.js playwright.living-paper.config.js
npm run test:e2e -- --config playwright.living-paper.config.js
npm run test:e2e -- e2e/lab-gallery.spec.js
```

전용 Playwright 설정은 기본 브라우저의 플래그를 바꾸지 않는다. 미지원 환경, 설치된 Chrome, Playwright의 전체 Chromium을 별도 프로젝트로 실행한다. Chrome 프로젝트는 로컬에 Google Chrome이 설치되어 있어야 한다. 기본 테스트 설정에서는 실험 플래그가 필요한 테스트를 건너뛰므로 네이티브 기능 확인에는 반드시 전용 설정을 사용한다.

브라우저 테스트는 실제 클릭 위치, 한글 조합 입력, 성공한 네이티브 업로드와 픽셀 변화, 텍스트 선택, 네 모서리 조작 후 재편집, 고해상도 화면과 리사이즈, 동작 줄이기, 그래픽 컨텍스트 손실 시 문서·재질·도장 보존을 확인한다. Chromium의 실제 접근성 트리도 조회한다. 파동·순간 바람은 GPU의 실제 정점 버퍼를 읽어 변형과 평면 복원을 확인한다. 320px 화면에서 Chrome DevTools Protocol의 터치 입력을 보내 모서리 조작과 재편집을 검증한다.

별도 시각 검토는 1440×900, 1280×720, 768×600, 390px와 320px 화면에서 수행했다. Chrome 152에서 `window.find`로 문서 내부 텍스트를 찾는 것을 확인했다. 1440×900, 장치 픽셀 비율 2의 로컬 Chrome에서 2초간 측정한 프레임 간격은 첫 확장 검토에서 중앙값 16.7ms, 95백분위 16.8ms였다. 최종 검토에서는 33.3ms/33.4ms였으며, 같은 브라우저의 빈 페이지에서도 동일했다. 그림자 필터 제거와 레이어 승격 비교에서도 변하지 않아 이 측정만으로 장면 자체의 성능 저하로 판단하지 않았다. 이 수치는 해당 장치의 짧은 측정 결과이며 다른 기기의 성능을 보장하지 않는다.

2026-09-17 확장 검증 결과: 단위 테스트 482개, Living Paper 브라우저 테스트 17개가 통과했다. 프로덕션 빌드와 변경 파일의 린트도 통과했다. 갤러리 회귀 테스트 31개는 최초 구현 때 통과했으며, 이번 확장에서는 갤러리와 등록 코드를 변경하지 않았다. 빌드에는 기존 Three.js 청크의 600kB 초과 경고가 남아 있다.

실제 모바일 기기의 가상 키보드와 VoiceOver 음성 안내는 수동 검증하지 않았다. 전체 저장소의 `npm run lint`는 기존 오류 313개로 실패하며, 이번 변경 파일의 린트 결과는 별도로 확인한다.

기존 `dev/fittingService.test.js:76`에서 간헐적으로 `Expected: "SOURCE_EXPIRED"`, `Received: "BUSY"`가 발생한다. 해당 서비스는 `job.status = 'complete'`를 먼저 설정하고 임시 디렉터리의 비동기 정리 이후에 `active = false`로 바꾸므로, 완료 상태만 기다리는 테스트와 다음 요청 사이에 경쟁 조건이 있다. 확장 전 기준 실행에서도 재현되었으며, 서비스 코드를 변경하지 않은 확장 후 최종 실행에서는 482개가 모두 통과했다.
